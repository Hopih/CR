# Подсказки к заданиям ControlWork

Открывай подсказки по одной: сначала попробуй сам, потом читай следующую. Полное решение — в ветке `cw/0N`:

```bash
git diff practice...cw/01
```

Все решения собраны и проверены запуском. На ветках 1–7 проходит и скрипт преподавателя `check_starters.py`. На 8 и 9 он падает, и так и должно быть: эти задания меняют протокол (`WIN 5`, `LOSE 42`), а скрипт ждёт старые ответы.

**Как устроен шаблон** (это стоит понять до любой задачи):

- `WebServer.HandleAsync` — весь роутинг. Метод не GET → сразу 405; путь `/api/rates` → курсы; путь из словаря `StaticFiles` → файл; иначе 404.
- Любое исключение `HttpRequestException` / `TaskCanceledException` / `JsonException` внутри обработчика превращается в **502** в общем `catch`. Ловить ошибки источника самому не нужно — достаточно, чтобы они долетели наверх.
- `RatesService.GetRatesAsync()` — единственное место, откуда приходят курсы. Он сам решает, брать кеш или идти в источник. Все новые методы сервиса начинаются с вызова `GetRatesAsync()`.
- Ответ — `WriteJsonAsync(response, код, объект)`. Ошибка — `WriteJsonAsync(response, 400, new { error = "текст" })` и сразу `return`.
- В JS всё строится в `loadRates()`: `fetch` → строки таблицы → `ratesBody.replaceChildren(...)`.
- В NumberGuess вся логика — `GameSession.HandleCommand(string)`: строка команды на вход, строка ответа на выход. Сеть в `Program.cs` трогать почти никогда не нужно.

## 1. Конвертер

<details><summary>Подсказка 1 — куда что писать</summary>

В `WebServer.HandleAsync` новая ветка `else if (path == "/api/convert")`, она вызывает отдельный метод-обработчик. Он читает `request.QueryString["from"]` и т.д., проверяет, вызывает метод сервиса, пишет ответ.
</details>

<details><summary>Подсказка 2 — как считать</summary>

Всё через рубли. Сделай словарь «код → рублей за 1 единицу»: `c.Value / c.Nominal` для каждой валюты и вручную `["RUB"] = 1`. Тогда `rate = rub[from] / rub[to]`, `result = amount * rate`.
</details>

<details><summary>Подсказка 3 — сумма с запятой</summary>

`decimal.TryParse(text.Replace(',', '.'), NumberStyles.Number, CultureInfo.InvariantCulture, out var amount)`. Без `InvariantCulture` на русской Windows точка не распарсится.
</details>

<details><summary>Подсказка 4 — выпадающие списки</summary>

Заполняй их в `loadRates()` после загрузки таблицы: `select.replaceChildren(...codes.map(code => new Option(code, code)))`. Запомни `select.value` до замены и верни после, иначе «Обновить» сбросит выбор пользователя.
</details>

## 2. Поиск

<details><summary>Подсказка 1 — параметр к существующему маршруту</summary>

Новый путь не нужен: в ветке `/api/rates` прочитай `QueryString["search"]`, `?.Trim() ?? ""`. Проверка длины → 400 ещё до вызова сервиса.
</details>

<details><summary>Подсказка 2 — не испортить кеш</summary>

`RatesResponse` — record. `rates with { Currencies = найденные }` создаёт **копию**, а закешированный объект остаётся целым. Если присвоить что-то в сам кеш, следующий посетитель увидит результат чужого поиска.
</details>

<details><summary>Подсказка 3 — сравнение без регистра</summary>

`c.Name.Contains(search, StringComparison.OrdinalIgnoreCase)` — работает и для кириллицы.
</details>

<details><summary>Подсказка 4 — задержка ввода</summary>

```js
let timer;
input.addEventListener('input', () => { clearTimeout(timer); timer = setTimeout(loadRates, 300); });
```
</details>

## 3. Сортировка

<details><summary>Подсказка 1 — проверка параметров</summary>

`sort is not ("code" or "name" or "rate")` → 400. Значения по умолчанию через `?? "code"`.
</details>

<details><summary>Подсказка 2 — ключ сортировки</summary>

`switch` по `sort`, в каждой ветке свой `OrderBy`. Для курса ключ `c => c.Value / c.Nominal`, иначе иена (курс за 100) встанет выше доллара. Для названий — `StringComparer.Create(CultureInfo.GetCultureInfo("ru-RU"), ignoreCase: true)`.
</details>

<details><summary>Подсказка 3 — кликабельные заголовки</summary>

Внутрь `<th>` положи `<button type="button" class="sort" data-sort="code">` — кнопка сама работает с клавиатуры. Стрелку проще всего рисовать CSS-ом по атрибуту `aria-sort="ascending"` / `"descending"` на `<th>`: `th[aria-sort="ascending"] .sort::after { content: " ▲"; }`.
</details>

## 4. Предыдущий курс

<details><summary>Подсказка 1 — откуда брать</summary>

В JSON источника у каждой валюты есть `"Previous"`. Добавь параметр `decimal Previous` в record `CurrencyRate` — он прочитается автоматически, отдельный запрос не нужен.
</details>

<details><summary>Подсказка 2 — вычисляемые поля</summary>

Внутри record можно объявить свойства только с `get`: `public decimal Change => ...;` — они попадут в JSON ответа сами. Не забудь `Previous > 0 ? ... : 0`, иначе деление на ноль.
</details>

<details><summary>Подсказка 3 — цвет</summary>

В JS — только класс: `cell.className = 'change up'`. В CSS — `.change.up { color: green; }`. Знак плюса даёт `Intl.NumberFormat('ru-RU', { signDisplay: 'exceptZero' })`. Таблица теперь из 6 колонок — поправь правило выравнивания `nth-child`.
</details>

## 5. Выбор даты

<details><summary>Подсказка 1 — URL архива</summary>

`date.ToString("yyyy/MM/dd", CultureInfo.InvariantCulture)` — **обязательно** с InvariantCulture: `/` в формате даты значит «разделитель текущего языка», на русской Windows получится `2026.10.23` и 404.
</details>

<details><summary>Подсказка 2 — 404 источника — это не ошибка</summary>

`GetFromJsonAsync` на 404 бросит исключение → у тебя будет 502. Нужен `GetAsync`, потом `if (response.StatusCode == HttpStatusCode.NotFound) return null;`, потом `EnsureSuccessStatusCode()` и `ReadFromJsonAsync<ProviderRates>()`.
</details>

<details><summary>Подсказка 3 — кеш по дате</summary>

`Dictionary<DateOnly, RatesResponse>` в сервисе + `SemaphoreSlim` вокруг «проверить → скачать → положить», как уже сделано для текущих курсов.
</details>

<details><summary>Подсказка 4 — max у поля даты</summary>

`toISOString()` даёт дату по UTC — ночью это будет «вчера». Собери строку из `getFullYear()`, `getMonth() + 1`, `getDate()` с `padStart(2, '0')`.
</details>

## 6. STATUS

<details><summary>Подсказка 1 — какое состояние хранить</summary>

Кроме `isPlaying` нужно отличать «не начинал» от «выиграл»: ещё одно поле `hasWon`. И две границы `low = 1`, `high = 100`, которые сбрасываются в `START`.
</details>

<details><summary>Подсказка 2 — сужение диапазона</summary>

На `GREATER`: `low = Math.Max(low, guess + 1)`. На `LESS`: `high = Math.Min(high, guess - 1)`. Max/Min — чтобы глупая попытка вне диапазона его не расширила.
</details>

<details><summary>Подсказка 3 — клиент</summary>

Ответ клиент разбирает в `switch`. Для ответов с числом внутри — `_ when response.StartsWith("STATUS PLAYING ") => ...` (ставить **перед** последним `_ =>`).
</details>

## 7. GIVEUP

<details><summary>Подсказка</summary>

Новый `case "GIVEUP":` — сначала проверка аргументов (`INVALID_ARGUMENTS`), потом состояния (`NOT_STARTED`), потом `isPlaying = false` и `$"ANSWER {secret}"`. Это задание короткое — 10 минут.
</details>

## 8. Попытки и рекорд

<details><summary>Подсказка 1 — счётчик</summary>

`attempts++` ставь **после** всех проверок `GUESS` (формат и `NOT_STARTED`) — тогда ошибки не считаются. Сброс — в `START`.
</details>

<details><summary>Подсказка 2 — рекорд</summary>

`GameSession` создаётся на каждого клиента, поэтому общий рекорд — `static` поле. Его меняют задачи разных клиентов одновременно, поэтому чтение и «сравнить + записать» — внутри `lock (RecordLock) { ... }`.
</details>

<details><summary>Подсказка 3 — клиент</summary>

`"WIN"` в клиенте больше не совпадёт точно, ответ теперь `"WIN 5"`. Замени ветку на `_ when response.StartsWith("WIN ") => ...`.
</details>

## 9. Лимит попыток

<details><summary>Подсказка 1 — аргумент запуска</summary>

В top-level `Program.cs` есть `args`. Проверь `args.Length > 0`, `int.TryParse`, диапазон; при ошибке — `Console.Error.WriteLine`, `Environment.ExitCode = 1; return;` — **до** открытия сокета.
</details>

<details><summary>Подсказка 2 — передать в игру</summary>

`HandleClientAsync` — статическая функция, переменных снаружи она не видит. Добавь ей параметр `int maxAttempts`, а `GameSession` дай конструктор: `public sealed class GameSession(int maxAttempts)`.
</details>

<details><summary>Подсказка 3 — порядок проверок</summary>

Сначала «угадал?» → `WIN`, и только потом «кончились попытки?» → `LOSE`. Иначе угадывание на последней попытке станет проигрышем.
</details>
