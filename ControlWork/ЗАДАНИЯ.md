# ControlWork — тренировочные задания

Вам даны проекты `CurrencyWeb`, `NumberGuessServer` и `NumberGuessClient` (описание — в [README.md](README.md)). Нужно внести изменения в проект по одному заданию.

Каждое задание независимо от остальных, поэтому не нужно учитывать требования из других заданий. Сосредоточьтесь только на своей задаче.

Ориентировочное время выполнения одного задания — **30 минут**.

Ветки в этом репозитории:

- `main` — шаблон преподавателя без изменений (`git pull` обновляет её как обычно);
- `practice` — то же самое, плюс эти задания и подсказки, а CurrencyWeb слушает порт **8081** вместо 8080 (на этом ноутбуке 8080 занят службой PEMHTTPD; `check_starters.py` поправлен так же). Сайт: http://localhost:8081/
- `cw/01` … `cw/09` — решения, каждое поверх `practice`.

Как тренироваться: заведи ветку от `practice`, реши, сравни с решением, вернись.

```bash
git switch -c try/01 practice
```

```bash
git diff practice...cw/01
```

```bash
git switch practice
```

Подсказки — в [ПОДСКАЗКИ.md](ПОДСКАЗКИ.md).

Общие правила для всех заданий:

- формат ошибок как в шаблоне: `{ "error": "текст" }`;
- в CurrencyWeb: `RatesService.cs` — внешний API, модели и логика, `WebServer.cs` — маршруты, чтение и проверка параметров, `public/` — страница;
- после изменений старое поведение из README продолжает работать: 404, 405, 502, кеш на 5 минут;
- в NumberGuess: обмен только через `Socket.SendAsync` / `Socket.ReceiveAsync`, без `NetworkStream`, `StreamReader` и других обёрток. Сначала проверяется формат команды, затем состояние игры.

# CurrencyWeb

## Задание 1. Конвертер валют

Необходимо добавить пересчёт суммы из одной валюты в другую по текущим курсам.

### Требуется реализовать

Endpoint:

```http
GET /api/convert?from=USD&to=EUR&amount=100
```

Пример ответа:

```json
{
  "from": "USD",
  "to": "EUR",
  "amount": 100,
  "result": 92.35,
  "rate": 0.9235,
  "date": "2026-10-27T11:30:00+03:00"
}
```

`rate` — сколько единиц `to` стоит одна единица `from`. `date` — дата курсов из источника.

### Логика

- `from` и `to` обязательны: три латинские буквы, регистр не важен (`usd` = `USD`);
- рубль (`RUB`) можно указывать с любой стороны, хотя в данных источника его нет;
- `amount` обязателен: число больше 0 и не больше 1 000 000 000; принимаются `1.5` и `1,5`;
- курс учитывает номинал: в источнике курс дан **за номинал** (иена — за 100 единиц);
- `result` округляется до 2 знаков, `rate` — до 4.

Ошибки:

| Код | Когда |
|---|---|
| 400 | код валюты не из трёх латинских букв или неверная сумма |
| 404 | валюты нет в курсах |
| 502 | источник курсов недоступен |

### Вёрстка

Над таблицей — форма: сумма, два выпадающих списка валют (RUB + все валюты из таблицы), кнопка «Конвертировать», строка результата вида `100 USD = 92,35 EUR`. Ошибка выводится там же, где результат.

### Обязательные требования

- курсы берутся из уже существующего кеша `RatesService`: конвертация не делает лишних запросов к источнику;
- расчёт — в `RatesService`, проверка параметров — в `WebServer`;
- деньги считать в `decimal`, не в `double`.

## Задание 2. Поиск валюты

Необходимо добавить поиск по коду и названию валюты.

### Требуется реализовать

Параметр у существующего endpoint'а:

```http
GET /api/rates?search=дол
```

Формат ответа не меняется: `{ date, currencies }`, только в `currencies` остаются подходящие валюты.

### Логика

- ищется подстрока в коде **или** в названии, без учёта регистра (`usd`, `Дол`, `фунт`);
- пробелы по краям игнорируются; пустой или отсутствующий `search` — все валюты;
- `search` длиннее 50 символов — `400`;
- ничего не найдено — `200` и пустой массив `currencies`.

### Вёрстка

- поле поиска над таблицей;
- запрос уходит при вводе, но не на каждую букву: через 300 мс после последнего нажатия;
- статус «Найдено валют: N»; если ничего не найдено — в таблице строка «Ничего не найдено»;
- кнопка «Обновить» учитывает текущий поиск.

### Обязательные требования

- фильтрация — в `RatesService`, после кеша: поиск не делает запросов к источнику;
- **кешированный объект не изменять**: для ответа создаётся новый.

## Задание 3. Сортировка таблицы

Необходимо добавить сортировку курсов по колонкам.

### Требуется реализовать

```http
GET /api/rates?sort=rate&order=desc
```

### Логика

- `sort`: `code` (по умолчанию), `name`, `rate`;
- `order`: `asc` (по умолчанию) или `desc`;
- сортировка по `rate` — по курсу **за одну единицу** (`value / nominal`), а не за номинал: иначе иена (за 100 единиц) окажется выше доллара;
- названия сравниваются по правилам русского языка без учёта регистра;
- недопустимое значение `sort` или `order` — `400` с текстом, какие значения допустимы.

### Вёрстка

- заголовки «Код», «Валюта», «Курс» кликабельны;
- клик по новой колонке сортирует по возрастанию, повторный клик по той же — меняет направление;
- у активной колонки стрелка ▲ или ▼.

### Обязательные требования

- сортировка — в `RatesService`, проверка параметров — в `WebServer`;
- кешированный массив не сортировать «на месте»;
- заголовки должны работать и с клавиатуры (Tab + Enter).

## Задание 4. Предыдущий курс и изменение

Необходимо показывать, как изменился курс по сравнению с предыдущим.

### Требуется реализовать

В данных источника у каждой валюты уже есть поле `Previous` — предыдущий курс (тоже за номинал). Добавить в ответ `/api/rates` для каждой валюты:

```json
{ "charCode": "USD", "name": "Доллар США", "nominal": 1, "value": 80.1234,
  "previous": 79.9876, "change": 0.1358, "changePercent": 0.17 }
```

### Логика

- `change` = `value − previous`, округление до 4 знаков;
- `changePercent` = изменение в процентах от `previous`, округление до 2 знаков;
- если `previous` равен 0 или отсутствует — `change` и `changePercent` равны 0 (без деления на ноль).

### Вёрстка

- новые колонки «Пред. курс» и «Изменение»;
- рост — зелёным со стрелкой ▲, падение — красным со стрелкой ▼, без изменений — серым;
- пример ячейки: `▲ +0,1358 (+0,17 %)`.

### Обязательные требования

- дополнительных запросов к источнику нет: всё есть в том же ответе;
- вычисления на сервере, а не в JavaScript;
- цвет задаётся CSS-классами, а не `element.style`.

## Задание 5. Курсы на выбранную дату

Необходимо дать возможность посмотреть курсы на любую прошедшую дату.

### Требуется реализовать

```http
GET /api/rates?date=2026-10-23
```

Источник архивных курсов:

```
https://www.cbr-xml-daily.ru/archive/2026/10/23/daily_json.js
```

Без `date` endpoint работает как раньше (текущие курсы).

### Логика

- формат `date` строго `yyyy-MM-dd`, иначе `400`;
- дата из будущего — `400`;
- архив ответил `404` (в этот день ЦБ курс не устанавливал: воскресенье, праздник, понедельник после субботы) — наш сервер отвечает `404` с понятным текстом;
- прочие ошибки источника — `502`;
- в ответе тот же формат `{ date, currencies }`.

### Вёрстка

- поле `<input type="date">`, кнопка «Показать», кнопка «Сегодня» (вернуться к текущим курсам);
- нельзя выбрать дату из будущего (`max`);
- подпись таблицы показывает дату курсов.

### Обязательные требования

- архивные курсы не меняются: каждая дата запрашивается у источника **не больше одного раза** за время работы сервера (кеш по дате);
- путь к архиву собирается из даты так, чтобы не зависеть от языка Windows;
- текущие курсы и их кеш на 5 минут работают как прежде.

# NumberGuess

## Задание 6. Команда STATUS

Необходимо добавить команду, показывающую состояние игры.

### Требуется реализовать

| Команда | Ответ | Когда |
|---|---|---|
| `STATUS` | `STATUS NOT_STARTED` | игра ещё ни разу не начиналась |
| `STATUS` | `STATUS PLAYING 51-100` | идёт игра; диапазон, в котором точно лежит число, с учётом подсказок |
| `STATUS` | `STATUS WON` | последний раунд выигран, новый не начат |
| `STATUS x` | `ERROR INVALID_ARGUMENTS` | лишние аргументы |

### Логика

- после `START` диапазон `1-100`;
- `GREATER` на `GUESS 50` сужает нижнюю границу до 51, `LESS` — верхнюю до 49;
- попытка за пределами уже известного диапазона границы не расширяет;
- `START` в середине игры сбрасывает диапазон.

### Клиент

Команда `status`: «Игра не начата», «Число от 51 до 100», «Последняя игра выиграна».

### Обязательные требования

- состояние хранится в `GameSession` и независимо для каждого клиента;
- остальные команды работают как раньше.

## Задание 7. Команда GIVEUP

Необходимо дать возможность сдаться и узнать число.

### Требуется реализовать

| Команда | Ответ | Когда |
|---|---|---|
| `GIVEUP` | `ANSWER 42` | идёт игра; раунд завершается |
| `GIVEUP` | `ERROR NOT_STARTED` | игра не идёт |
| `GIVEUP x` | `ERROR INVALID_ARGUMENTS` | лишние аргументы |

### Логика

- после `ANSWER` игра закончена: `GUESS` даёт `ERROR NOT_STARTED`, нужен новый `START`.

### Клиент

Команда `giveup`: «Вы сдались. Было загадано 42. Для новой игры введите start.»

## Задание 8. Счётчик попыток и рекорд сервера

Необходимо считать попытки и хранить лучший результат среди всех игроков.

### Требуется реализовать

| Команда | Ответ | Когда |
|---|---|---|
| `GUESS 42` | `WIN 5` | угадано с 5-й попытки (вместо простого `WIN`) |
| `RECORD` | `RECORD 3` | лучший результат среди всех игроков сервера |
| `RECORD` | `RECORD NONE` | ещё никто не выигрывал |
| `RECORD x` | `ERROR INVALID_ARGUMENTS` | лишние аргументы |

### Логика

- считаются только корректные попытки во время игры; ошибки не считаются;
- `START` сбрасывает счётчик;
- рекорд — минимальное число попыток среди всех побед на этом сервере, общий для всех подключений; после перезапуска сервера рекорда нет.

### Клиент

«Вы угадали! Попыток: 5. Для новой игры введите start.»; команда `record`: «Рекорд сервера — попыток: 3» / «Рекорда пока нет».

### Обязательные требования

- рекорд меняют задачи разных клиентов одновременно — обновление должно быть потокобезопасным.

## Задание 9. Ограничение попыток

Необходимо ограничить число попыток в раунде.

### Требуется реализовать

- лимит попыток передаётся серверу аргументом при запуске: `dotnet run --project NumberGuessServer -- 10`; по умолчанию 7;
- допустимый лимит — от 1 до 20; иначе сервер пишет ошибку и не запускается;
- если попытка с номером, равным лимиту, не угадала — вместо `GREATER`/`LESS` ответ `LOSE 42` (загаданное число), раунд завершён.

### Логика

- считаются только корректные попытки во время игры;
- после `LOSE` — как после победы: `GUESS` даёт `ERROR NOT_STARTED`;
- угадывание на последней попытке — обычный `WIN`.

### Клиент

«Попытки закончились. Было загадано 42. Для новой игры введите start.»

### Обязательные требования

- лимит передаётся в `GameSession` (через конструктор), а не хранится глобальной переменной;
- при лимите 7 стратегия «делить пополам» по-прежнему всегда выигрывает.
