# Протокол WordGuesser

Общая библиотека для клиента и сервера, .NET 8. Содержит команды, кодирование
полезной нагрузки, упаковку и транспорт. Серверная модель сессий и обработчики
команд остаются в `WordGuesserServer`.

## Формат

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 1 байт | Начало: `0x02` |
| 1 | 1 байт | Код команды |
| 2 | 1 байт | Длина полезной нагрузки N, от 0 до 96 |
| 3 | N байт | Полезная нагрузка |
| 3 + N | 1 байт | Конец: `0x03` |

Полный пакет занимает от 4 до 100 байт. Граница определяется длиной,
а не поиском `0x03`: байты `0x02` и `0x03` могут встречаться внутри данных.

Текст — UTF-8 без BOM, с отклонением некорректных последовательностей.
GUID — 36 символов в формате `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.
Роль — 32-битное целое в little-endian: Hosted = 1000, Guesser = 2000.
Код ответа — один байт, без заголовка внутри полезной нагрузки.

Лимит 96 применяется к **байтам**, а не символам. У `Word` и `Guess` GUID и
двоеточие занимают 37 байт: на слово остаётся 59 байт. Например, помещаются
29 русских букв либо 59 английских. Проверка допустимых букв, нормализация
регистра и сравнение длины слов относятся к будущей игровой логике.

## Команды на текущем этапе

К → С: клиент отправляет серверу; С → К: сервер отправляет клиенту.
Таблица фиксирует формат сообщений. Проверки игровых состояний будут добавлены
в итерациях сервера и игрового цикла.

| Код | Команда | Направление | Данные | Назначение |
| --- | --- | --- | --- | --- |
| `0x05` | ReadyToGuess | С → К | Непустая строка UTF-8 | Начальная маска |
| `0x06` | CommandResponse | С → К | Один известный код ответа | Подтверждение или ошибка |
| `0x10` | Create | К → С | Нет | Создать сессию |
| `0x11` | SessionId | С → К | GUID | Идентификатор сессии |
| `0x20` | Join | К → С | GUID | Подключиться к сессии |
| `0x21` | Ready | С → К | Роль, 4 байта | Назначить роль |
| `0x30` | Word | К → С | `GUID:слово` | Задать слово |
| `0x40` | Guess | К → С | `GUID:попытка` | Отправить попытку |
| `0x41` | GuessResult | С → К | Непустая строка UTF-8 | Маска текущей попытки |
| `0x50` | Win | С → К | Непустая строка UTF-8 | Отгаданное слово |
| `0x51` | Swap | К → С | Нет | Существующая команда смены ролей |
| `0x52` | End | К ↔ С | Нет | Завершение сессии |

В `Word` и `Guess` после GUID требуется непустой текст, не состоящий только
из пробелов и не содержащий дополнительного двоеточия.

Коды ответа: `0` — Ok, `1` — PlayerNotJoined, `2` — IncorrectSender,
`3` — CommandIncorrect, `4` — PackageIncorrect, `5` — SessionNotFound.

В дальнейшей итерации роли будут меняться автоматически. Также потребуется
разделить события конца раунда и матча, передавать счёт и остаток попыток.
Текущие `Win` и `End` ещё не выражают весь согласованный игровой цикл.

## Упаковка и проверка

- `GuessCommandHelper` возвращает готовые пакеты и проверяет формат данных.
- `GuessPackageBuilder` и `GuessPackageParser` работают только с оболочкой пакета.
  Парсер не проверяет смысл полезной нагрузки.
- `GuessCommandHelper.Decode` проверяет данные конкретной команды. Некорректные
  данные или неверный запрошенный тип приводят к `FormatException`, без подстановки
  значений по умолчанию.
- `DecodeSessionWithData` возвращает GUID и текст для `Word` и `Guess`.

## Работа с TCP

Весь обмен выполняется через `socket.SendPacketAsync(...)` и
`socket.ReceivePacketAsync(...)`. Они используют один `GuessConnection` на сокет.
Не следует смешивать их с прямыми чтениями/записями сокета или создавать другую
обёртку для того же соединения.

Приём сначала дочитывает заголовок, затем указанное число байтов и конец пакета.
Остальные байты остаются в TCP-потоке для следующего вызова. Поэтому разделение
пакета между чтениями и объединение нескольких пакетов обрабатываются одинаково.

Отправка использует `NetworkStream.WriteAsync`, записывающий весь переданный
буфер. Отдельный семафор сериализует отправки: байты разных пакетов не смешиваются.
Приём также сериализован, но может выполняться одновременно с отправкой.

Транспорт владеет потоком и сокетом. Нормальный EOF между пакетами возвращает
`null` и закрывает соединение. EOF внутри пакета приводит к `EndOfStreamException`.
Некорректные границы, превышение длины или неизвестный код команды приводят к
`InvalidDataException`. Ошибки ввода-вывода и отмена уже начатой операции закрывают
соединение: после частичного обмена повторное использование небезопасно.
Отмена ожидания семафора не закрывает соединение.

Если оболочка корректна, но данные команды неверны, сервер отвечает
`PackageIncorrect` и продолжает чтение. Для известной команды, которую сервер
не обрабатывает, он отвечает `CommandIncorrect`. При повреждении самой оболочки
соединение закрывается без попытки восстановить границы по случайным байтам.
Клиент закрывает соединение при некорректном серверном сообщении.

Новая версия сохраняет коды команд и оболочку, но обе стороны следует обновлять
вместе: старый ASCII-клиент не поддерживает русские слова. Согласования версии
протокола пока нет.
